2026-07-26 — PDF 도면을 CSS로 살아나게 만들다가 겪은 SVG transform 함정

프리랜서 전장 설계 홈페이지의 첫 화면을, "빈 종이 위에 진짜 회로도가 선 하나씩 그려지고 심벌이 툭툭 떨어져 조립되는" 애니메이션으로 만들기로 했다. 그럴듯한 가짜 회로도가 아니라 실제로 작업했던 PDF 도면을 그대로 써야 한다는 게 조건이었다. PyMuPDF로 벡터 데이터를 뽑아 SVG로 재조립하면 되겠다 싶었는데, 그 사이에 원인을 찾는 데만 한참 걸린 버그가 두 개 있었다.

첫 번째 함정 — 멀쩡한 선이 반쯤 사라진다

PDF에서 선·도형·텍스트를 뽑아 크롭 영역 안의 것만 골라내는 코드를 짰다. 크롭 밖으로 나가는 요소는 fitz.Rect.intersects()로 걸러내는 흔한 방식이었다. 결과물을 원본과 겹쳐보니 굵은 접지선 하나가 통째로 빠져 있었다.


원본 PDF 렌더링과 내 SVG 렌더링을 픽셀 단위로 비교한 결과. 빨간 선이 "원본엔 있는데 내 결과물엔 없는" 부분이다.

원인은 intersects() 자체였다. 완전히 수평이거나 수직인 선분은 폭이나 높이가 0인 사각형이 되는데, 면적이 0인 도형에 대해 이 함수가 겹침 판정을 제대로 못 했다. 개별 선 하나둘이 아니라 두께 0짜리 도형 전체가 조용히 탈락하고 있었던 것이다.

해결은 라이브러리 함수를 믿지 않고 직접 짜는 것이었다.

def overlaps(r, crop):
    # fitz.Rect.intersects()는 두께 0인 선분(완전 수평/수직)에서 오작동한다.
    return r.x0 <= crop.x1 and r.x1 >= crop.x0 and r.y0 <= crop.y1 and r.y1 >= crop.y0

이 한 줄로 바꾸자 누락됐던 선들이 전부 돌아왔다.

두 번째 함정 — 회전한 글자가 전부 겹쳐 보인다

원본 도면엔 세로로 회전된 라벨이 많다("R", "S", "T" 같은 배선 색상 표기). PyMuPDF의 get_text("dict")가 주는 회전 각도를 읽어 SVG transform="rotate(...)"로 그대로 옮겨줬더니, 정적인 화면에서는 완벽하게 나왔다.

문제는 여기에 "낙하 애니메이션"을 얹었을 때 터졌다. 이 텍스트들을 감싼 <g>에 CSS animation으로 transform: translateY(...) rotateX(...)를 걸었더니, 회전이 통째로 사라지고 글자들이 가로로 겹쳐서 렌더링됐다.

CSS transform 속성(property)이 SVG의 transform 어트리뷰트(attribute)를 합성하지 않고 완전히 대체한다는 게 원인이었다. 애니메이션의 마지막 프레임이 transform: translateY(0) rotateX(0)처럼 "사실상 아무것도 안 하는" 값이어도, 그 자체가 이미 attribute를 덮어써서 원래 있던 회전은 사라진다.

해결책은 역할을 분리하는 것이었다.

역할 담당 요소 예시
낙하 애니메이션 (CSS transform) 바깥쪽 <g> <g style="animation: dropSnap ...">
고정 회전 (SVG 속성) 안쪽 <text> <text transform="rotate(-90 x y)"> 
<g style="animation-delay:1.28s;">
  <text x="104.0" y="82.9" transform="rotate(-90.0 104.0 82.9)">4 SQ-흑</text>
</g>

바깥은 CSS로 움직이고, 안쪽은 어트리뷰트로 고정 회전만 담당하니 둘이 서로 안 건드리게 됐다.


각 라벨이 자기 배선 아래 정확히 세로로 정렬됐다. 고치기 전엔 4개 라벨이 한 줄에 뭉개져 있었다.

결과

두 버그를 잡고 나니, 실제 도면 전체(제목란만 고객 정보라 제외)가 종이 위로 떨어져 조립되는 애니메이션이 완성됐다. 선 굵기도 원본 그대로 따라가되(PDF 자체의 불규칙한 굵기는 정규화), 진짜 도면 좌표를 그대로 쓰다 보니 신뢰도가 확 올라갔다.


3단계로 나눠 아래로 스크롤되며 조립되는 버전. 다음엔 이 3단계 점프를 연속적인 스크롤로 바꾸는 작업이 남아있다.

배운 것 / 다음에 할 일

라이브러리 함수는 "면적 0"처럼 극단적인 입력값에서 조용히 실패할 수 있다는 걸 다시 확인했다 — 의심 가면 직접 겹침 판정을 짜는 게 빠르다. 그리고 SVG에 CSS 애니메이션을 얹을 땐, 움직임(CSS)과 고정 형태(속성)를 같은 요소에 두지 않는다는 원칙을 세웠다. 다음 작업은 지금 3단계로 끊어서 스크롤하는 걸 처음부터 끝까지 자연스럽게 흘러가는 연속 스크롤로 바꾸는 것 — 이건 할당량이 다 돼서 커서(Cursor)에게 인수인계했다.
